# PromQL Examples

## 1. Instant query

```promql
up
```

- **What it does:** Returns the current value of the `up` metric for every scrape target Prometheus knows about. `up` is automatically generated by Prometheus itself for every target.
- **Data type returned:** Instant vector — one value (1 or 0) per target/time series, at the current moment.
- **When to use it:** To quickly check which targets are currently reachable (`1`) or down (`0`).
- **Practical use case:** Building a dashboard panel or alert rule like `up == 0` to detect targets that are currently unreachable.

## 2. Range query

```promql
rate(http_requests_total[5m])
```

- **What it does:** Calculates the average per-second rate of increase of the `http_requests_total` counter, computed over each 5-minute window.
- **Data type returned:** Instant vector (one rate value per series) when run as a single query; when plotted over time (a range query in the API sense), it becomes a matrix showing the rate trend over time.
- **When to use it:** Whenever you need the *rate of change* of a counter rather than its raw cumulative value — counters are always increasing, so raw values aren't directly meaningful on their own.
- **Practical use case:** Graphing request throughput (requests/sec) for a web service over time.

## 3. Selector with labels

```promql
http_requests_total{method="GET", status="200"}
```

- **What it does:** Selects only the raw counter values of `http_requests_total` where the `method` label is `"GET"` and the `status` label is `"200"`.
- **Data type returned:** Instant vector — the current raw (cumulative) counter value for each matching series.
- **When to use it:** When you want to inspect or filter to a specific subset of a metric's time series based on its labels, before applying further functions.
- **Practical use case:** Debugging or verifying that a specific type of request (successful GETs) is being tracked correctly, or as the base selector inside a larger expression (e.g., wrapped in `rate()`).

## 4. Aggregation

```promql
sum(http_requests_total) by (method)
```

- **What it does:** Sums the values of all `http_requests_total` series together, but groups the result by the `method` label, so you get one total per HTTP method (GET, POST, etc.) instead of one grand total or one value per individual series.
- **Data type returned:** Instant vector — one aggregated value per unique `method` label value.
- **When to use it:** When there are many time series for the same metric (e.g., broken down by `instance`, `path`, `status`, etc.) and you want a combined view grouped by a specific dimension.
- **Practical use case:** Seeing total request volume per HTTP method across all instances of a service, without needing to look at each instance individually.

## 5. Function

```promql
increase(http_requests_total[1h])
```

- **What it does:** Calculates the total increase (not rate) of the `http_requests_total` counter over the past 1 hour — essentially answering "how many requests came in during the last hour?"
- **Data type returned:** Instant vector — one value per series representing the total increase over the specified time window.
- **When to use it:** When you want an absolute count over a period, rather than a per-second rate. Useful for reporting or threshold-based alerts on total volume.
- **Practical use case:** Alerting if fewer than N requests were received in the last hour (potential traffic drop), or reporting total requests processed per hour in a summary dashboard.
